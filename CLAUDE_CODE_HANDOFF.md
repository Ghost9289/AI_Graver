# AI Graver — передача проекта для Claude Code

## Где находится проект

Начиная с v0.8.0 код живёт в GitHub-репозитории `Ghost9289/AI_Graver` (ветка `main`), это источник истины — не копия на диске. Клонировать себе:

```powershell
git clone https://github.com/Ghost9289/AI_Graver.git
cd AI_Graver
```

`models/GFPGANv1.4.onnx` (324 МБ) в git не хранится — см. `PUBLISH_RELEASE.md`, раздел «Разовая настройка: модель GFPGAN», как его получить/куда положить локально для запуска из исходников (в собранный `.exe` он попадает автоматически через CI, скачивать руками нужно только для `py app.py`).

Не выполнять `git reset --hard`, `git clean`, `rebase` или `force push` в этом репозитории без явного разрешения пользователя.

## Graver 5

Рабочий путь пользователя:

```text
C:\Users\rf-rt\OneDrive\Рабочий стол\Программы\Гравер 5.22.8 — копия\graver5_x64.exe
```

Рядом находятся `conf.ini` и `graver.log`. Файл `conf.ini` использует кодировку CP1251 и содержит завершающий нулевой байт — это нужно сохранить при изменениях.

Graver по журналу использует тоновые слои и умеет читать BMP. Рабочие параметры экспорта AI Graver:

```text
8-bit grayscale (L)
3084 × 5526 px
83 DPI
PNG + BMP
```

## Последние изменения v0.7.0

Изменены `app.py`, `graver_bridge.py`, `version.py`, `installer.iss` и `README.md`.

1. Приложение автоматически находит `graver5_x64.exe` по указанному выше пути.
2. Кнопка называется «Проверить в Graver».
3. Для Graver создаётся отдельный `portrait_for_graver.bmp`, а не передаётся PNG.
4. BMP создаётся через Pillow как `L`, `3084×5526`, `83 DPI`.
5. Вместо ненадёжной команды «открыть последний» автоматизация открывает штатное окно выбора файла Graver, подставляет путь к BMP и подтверждает Enter.
6. После передачи код ждёт запись в `graver.log` (`BM NewSize`) и сообщает, подтверждён ли разбор файла.
7. **Никакие команды CNC/запуска гравировки не отправляются.** Оператор всегда вручную проверяет портрет и запускает станок.

Проверка на реальном Graver выполнялась: файл передавался в его окно открытия, а в `graver.log` появилась строка `BM NewSize 1968 2756`. Также проверен сформированный BMP: режим `L`, размер `3084×5526`, DPI `83×83`.

## Текущие возможности

- JPG/PNG/BMP/TIFF.
- Автоматическое удаление фона, чёрный фон.
- Кадрирование «до груди» или «полный рост».
- Профили камня: чёрный гранит/Карелия, серый гранит, мрамор.
- Ползунки контраста, детализации, теней; автоматическое обновление предпросмотра.
- GFPGAN 1.4 для восстановления лица и отдельный файл `*_restored_4k.png`.
- Итог `*_graver_ready.png` и `*_graver_ready.bmp` в `%APPDATA%\AI Graver\output`.
- Автообновление через GitHub Releases уже подготовлено, но новую версию нужно публиковать в релизе GitHub отдельно.

Real-ESRGAN пробовали — на CPU ~20 сек/тайл 160×160, для целого портрета неприемлемо, поэтому не используется.
2. В интерфейсе (`app.py`) выпадающий список «Естественно / Сильное восстановление / Старое фото» под галочкой AI-реконструкции (`EngravingOptions.restoration_mode`, `config_store.py`). В strong/old_photo дополнительно отключается `_adaptive_tone` — автоматическое приглушение контраста/детализации/теней на «уже хороших» фото.
3. После обработки — кнопки «Сохранить как…» и «Открыть в Graver» (раньше в реально используемом `_build_compact_ui` такой кнопки не было вообще, только автоматический запуск через «Полный автомат»). Запуск Graver перенесён в фоновый поток — раньше `launch_graver_with_image` блокировал GUI на время ожидания окон (до ~35 сек).
4. Удалённый выключатель: `status.json` в репозитории, проверяется при старте (см. `updater.check_remote_access`), fail-open при отсутствии сети.
5. Автосборка через GitHub Actions по тегу `vX.Y.Z` (модель GFPGAN качается из отдельного релиза `models-v1`, т.к. 324 МБ не проходит обычный `git push`).

## Активная проблема: шум/испещрённость на grayscale-результате

Пользователь прислал скриншот с v0.8.0: после обработки (портретное фото, отсканированная печать с полутоновым растром, галочка «Удалять фон», «Полный автомат», режим «Сильное восстановление») правая панель («ГОТОВО ДЛЯ GRAVER») показывает сильно зашумлённое/испещрённое изображение — не похоже на нормальный grayscale-результат.

Проверено пользователем: **на «Естественно» то же самое** — значит, проблема не специфична для нового restoration_mode (в «Естественно» логика `_enhance_source_resolution`/`_adaptive_tone` не менялась).

Проверено мной на Linux (тот же файл-источник, тот же `EngravingOptions`, включая `mediapipe` для удаления фона): **шум не воспроизводится** — ни в полном разрешении, ни в превью (390×700), ни в natural, ни в strong. Картинки чистые. То есть проблема специфична для реального Windows-запуска (собранный `.exe` или его окружение), а не для кода как такового при том же входе.

Что ещё не проверено — это и есть следующий шаг:

1. Получить от пользователя реальный файл `*_graver_ready.png` (не скриншот) — смотреть точные пиксели.
2. Проверить, воспроизводится ли на **другом** фото (не только на этом сканированном с растром) — если только на этом конкретном источнике, подозревать взаимодействие полутонового растра с чем-то на Windows-сборке (например другая версия/поведение mediapipe или onnxruntime в PyInstaller-бандле против pip-версий на Linux).
3. Проверить, не через собранный ли `.exe` идёт тест, а не `py app.py` из исходников — если баг пропадает при запуске из исходников на той же Windows-машине, дело в самой PyInstaller-сборке (возможно, повреждённая/иначе оптимизированная модель в бандле).
4. Дальше не трогать `_adaptive_tone`/`restoration_mode` — раз баг в «Естественно» тоже есть, это не туда копать.

## Запуск и сборка

Для запуска из исходников:

```powershell
py -m pip install -r requirements.txt
py app.py
```

Для новой Windows-сборки:

```powershell
.\build_exe.ps1
```

Сборка тяжёлая из-за моделей и может занимать 10–15 минут. Результат установщика появляется в `installer\AI_Graver_Setup_v<версия>.exe`.

## Правило безопасности

Разрешена автоматизация подготовки изображения и его открытия в Graver. Не автоматизировать отправку CNC-команд, начало гравировки, движение станка или обход пользовательской проверки результата.
