# Разовая настройка: модель GFPGAN

`models/GFPGANv1.4.onnx` весит 324 МБ — GitHub блокирует обычный `git push` для файлов
больше 100 МБ, поэтому этот файл **не хранится в git**. Сборка (`.github/workflows/release.yml`)
скачивает его перед PyInstaller из отдельного Release-ассета репозитория. Настройте это
один раз, до первого тега с версией приложения:

1. Откройте `https://github.com/Ghost9289/AI_Graver/releases/new`.
2. В поле Tag укажите `models-v1`, в заголовке — что угодно, например «Model assets».
3. Перетащите файл `models/GFPGANv1.4.onnx` со своего компьютера в поле вложений.
4. Опубликуйте релиз (Publish release). Отмечать его как pre-release не обязательно.

Имя файла и тег `models-v1` должны совпадать с тем, что скачивает workflow — если понадобится
заменить модель, загрузите новый файл в этот же релиз с тем же именем или обновите URL в
`.github/workflows/release.yml`.

# Как включить автообновления

Автообновления используют GitHub Releases репозитория `Ghost9289/AI_Graver`.

1. Загрузите содержимое этой папки в репозиторий, включая `.github/workflows/release.yml`.
2. Создайте и отправьте тег версии, например `v0.2.0`:

```powershell
git add .
git commit -m "AI Graver v0.2.0"
git tag v0.2.0
git push origin main --tags
```

3. GitHub Actions сам соберёт установщик и создаст Release.

Версия приложения и имя установщика автоматически берутся из тега. После появления Release установленная программа найдёт новую версию при запуске, скачает её по кнопке, тихо установит и перезапустится. Закрывать программу или запускать установщик вручную не потребуется.

## Как удалённо заблокировать программу

При старте (до появления окна) программа читает `status.json` из корня ветки `main` репозитория `Ghost9289/AI_Graver` через GitHub API. Если файла нет или нет интернета — программа запускается как обычно (fail-open, чтобы офлайн-пользователя не заблокировало случайно).

Чтобы отключить программу у конкретной переданной копии:

1. Откройте `https://github.com/Ghost9289/AI_Graver/edit/main/status.json` в браузере (не нужен git на компьютере).
2. Поставьте `"enabled": false`, при желании поменяйте `"message"` — этот текст увидит пользователь в окне ошибки.
3. Сохраните commit прямо на GitHub.

При следующем запуске (с интернетом) программа покажет это сообщение и сразу закроется, не открывая рабочее окно. Чтобы вернуть доступ — верните `"enabled": true` тем же способом.

GitHub API кэширует `raw`-ответы на несколько минут, так что изменение может подействовать не мгновенно, а в течение 1–5 минут.
